Hướng dẫn về dòng lệnh
======================

.. highlight:: shell

Một số developer thích sử dụng dòng lệnh cho hầu hết công việc. Godot được thiết kế để hỗ trợ tốt những người dùng này, vì vậy dưới đây là các bước để làm việc hoàn toàn từ dòng lệnh. Vì engine hầu như không phụ thuộc vào thư viện bên ngoài nào, thời gian khởi tạo khá nhanh, khiến quy trình làm việc này trở nên phù hợp.

.. note::

    Trên Windows và Linux, bạn có thể chạy binary Godot trong terminal bằng cách chỉ định đường dẫn tương đối hoặc tuyệt đối của nó.

    Trên macOS, quy trình này khác do Godot được chứa trong một ``.app`` bundle (là một *thư mục*, không phải tệp). Để chạy binary Godot từ terminal trên macOS, bạn phải ``cd`` đến thư mục chứa application bundle của Godot, sau đó chạy ``Godot.app/Contents/MacOS/Godot`` kèm theo mọi đối số dòng lệnh. Nếu bạn đã đổi tên application bundle từ ``Godot`` thành tên khác, hãy nhớ chỉnh sửa dòng lệnh này cho phù hợp.

**Chú giải**

- |release| Có trong các bản build của editor, debug export template và release export template.
- |debug| Chỉ có trong các bản build của editor và debug export template.
- |extended| Chỉ có trong các bản build của editor và export template được biên dịch với ``disable_path_overrides=false``.
- |editor| Chỉ có trong các bản build của editor.

Lưu ý rằng các đối số dòng lệnh không xác định hoàn toàn không có tác dụng. Engine sẽ **không** cảnh báo bạn khi sử dụng một đối số dòng lệnh không tồn tại với một loại bản build nhất định.

Đường dẫn
---------

Bạn nên đặt tệp nhị phân Godot editor vào biến môi trường ``PATH`` để có thể dễ dàng thực thi từ bất kỳ đâu bằng cách nhập ``godot``. Trên Linux, bạn có thể thực hiện việc này bằng cách đặt tệp nhị phân Godot vào ``/usr/local/bin`` và đảm bảo tên của tệp là ``godot`` (phân biệt chữ hoa chữ thường).

Để dễ dàng thực hiện việc này trên Windows hoặc macOS, bạn có thể cài đặt Godot bằng `Scoop <https://scoop.sh>`__ (trên Windows) hoặc `Homebrew <https://brew.sh>`__ (trên macOS). Thao tác này sẽ tự động cung cấp bản Godot đã cài đặt trong ``PATH``:

.. tabs::

 .. code-tab:: sh Windows

    # Thêm bucket "Extras"
    scoop bucket add extras

    # Editor tiêu chuẩn:
    scoop install godot

    # Editor có hỗ trợ C# (sẽ khả dụng dưới dạng `godot-mono` trong `PATH`):
    scoop install godot-mono

 .. code-tab:: sh macOS

    # Editor tiêu chuẩn:
    brew install godot

    # Editor có hỗ trợ C# (sẽ khả dụng dưới dạng `godot-mono` trong `PATH`):
    brew install godot-mono

Thiết lập đường dẫn project
---------------------------

Tùy thuộc vào vị trí của tệp nhị phân Godot và thư mục làm việc hiện tại, bạn có thể cần thiết lập đường dẫn đến project để bất kỳ lệnh nào sau đây cũng hoạt động chính xác.

Khi chạy editor, bạn có thể thực hiện việc này bằng cách cung cấp đường dẫn đến tệp ``project.godot`` của project dưới dạng đối số đầu tiên, như sau:

::

    godot path_to_your_project/project.godot [other] [commands] [and] [args]

Với tất cả các lệnh, bạn có thể thực hiện việc này bằng cách sử dụng đối số ``--path``:

::

    godot --path path_to_your_project [other] [commands] [and] [args]

Ví dụ, lệnh đầy đủ để export game (như giải thích bên dưới) có thể trông như sau:

::

    godot --headless --path path_to_your_project --export-release my_export_preset_name game.exe

Khi bắt đầu từ một thư mục con của project, hãy sử dụng đối số ``--upwards`` để Godot tự động tìm tệp ``project.godot`` bằng cách tìm kiếm đệ quy trong các thư mục cha.

Ví dụ, việc chạy một scene (như giải thích bên dưới) nằm trong một thư mục con có thể trông như sau khi thư mục làm việc hiện tại nằm trong cùng đường dẫn:

::

    godot --upwards nested_scene.tscn


..

Tạo project
-----------


Bạn có thể tạo project từ command line bằng cách điều hướng shell đến vị trí mong muốn và tạo tệp ``project.godot``.


::

    mkdir newgame
    cd newgame
    touch project.godot


Giờ đây, bạn có thể mở project bằng Godot.


Chạy editor
-----------

Để chạy editor, hãy thực thi Godot với flag ``-e``. Việc này phải được thực hiện từ trong thư mục project hoặc bằng cách thiết lập đường dẫn project như đã giải thích ở trên; nếu không, lệnh sẽ bị bỏ qua và Project Manager sẽ xuất hiện.

::

    godot -e

Khi truyền vào đường dẫn đầy đủ đến tệp ``project.godot``, có thể bỏ qua flag ``-e``.

Nếu một scene đã được tạo và lưu, bạn có thể chỉnh sửa scene đó sau này bằng cách chạy cùng đoạn mã với scene đó làm đối số.

::

    godot -e scene.tscn

Xóa scene
---------

Godot thân thiện với filesystem của bạn và sẽ không tạo thêm các tệp metadata. Sử dụng ``rm`` để xóa tệp scene. Hãy đảm bảo không có gì tham chiếu đến scene đó. Nếu không, lỗi sẽ xảy ra khi mở project.

::

    rm scene.tscn

Chạy game
---------

Để chạy game, hãy thực thi Godot trong thư mục project hoặc với đường dẫn project như đã giải thích ở trên.

::

    godot

Lưu ý rằng việc truyền tệp ``project.godot`` luôn chạy editor thay vì chạy game.

Khi cần kiểm thử một scene cụ thể, hãy truyền scene đó vào command line.

::

    godot scene.tscn

Debug
-----

Việc bắt lỗi trong command line có thể khó khăn vì các lỗi cuộn qua rất nhanh. Để giải quyết vấn đề này, một command line debugger được cung cấp bằng cách thêm ``-d``. Tính năng này hoạt động khi chạy cả game lẫn một scene riêng lẻ.

::

    godot -d

::

    godot -d scene.tscn

.. _doc_command_line_tutorial_exporting:

Export
------

Bạn cũng có thể export project từ command line. Điều này đặc biệt hữu ích cho các thiết lập continuous integration.

.. note::

    Việc sử dụng đối số command line ``--headless`` là **bắt buộc** trên các nền tảng không có quyền truy cập GPU (chẳng hạn như continuous integration). Trên các nền tảng có quyền truy cập GPU, ``--headless`` ngăn không cho cửa sổ xuất hiện trong khi project đang được export.

::

    # `godot` must be a Godot editor binary, not an export template.
    # Also, export templates must be installed for the editor
    # (or a valid custom export template must be defined in the export preset).
    godot --headless --export-release "Linux/X11" /var/builds/project
    godot --headless --export-release Android /var/builds/project.apk

Tên preset phải khớp với tên của một export preset được định nghĩa trong tệp ``export_presets.cfg`` của project. Nếu tên preset chứa dấu cách hoặc ký tự đặc biệt (chẳng hạn như "Windows Desktop"), tên đó phải được đặt trong dấu ngoặc kép.

Để export phiên bản debug của game, hãy sử dụng switch ``--export-debug`` thay cho ``--export-release``. Tham số và cách sử dụng của chúng giống nhau.

Để chỉ export tệp PCK, hãy sử dụng tùy chọn ``--export-pack``, theo sau là tên preset và đường dẫn đầu ra có phần mở rộng tệp, thay cho ``--export-release`` hoặc ``--export-debug``. Phần mở rộng của đường dẫn đầu ra quyết định định dạng package, là PCK hoặc ZIP.

.. warning::

    Khi chỉ định đường dẫn tương đối làm đường dẫn cho ``--export-release``, ``--export-debug`` hoặc ``--export-pack``, đường dẫn đó sẽ tương đối với thư mục chứa tệp ``project.godot``, **không** tương đối với thư mục làm việc hiện tại.

Chạy script
-----------

Bạn có thể chạy một script ``.gd`` từ command line. Tính năng này đặc biệt hữu ích trong các project lớn, ví dụ như để chuyển đổi hàng loạt asset hoặc import/export tùy chỉnh.

Script phải kế thừa từ ``SceneTree`` hoặc ``MainLoop``.

Sau đây là một ``sayhello.gd`` mẫu, minh họa cách hoạt động:

.. code-block:: python

    #!/usr/bin/env -S godot -s
    extends SceneTree

    func _init():
        print("Hello!")
        quit()

Và cách chạy nó:

::

    # Prints "Hello!" to standard output.
    godot -s sayhello.gd

Nếu không tồn tại ``project.godot`` tại đường dẫn, đường dẫn hiện tại sẽ được giả định là thư mục làm việc hiện tại (trừ khi chỉ định ``--path``).

Đường dẫn script sẽ được diễn giải là một đường dẫn resource tương đối với project, ở đây là ``res://sayhello.gd``. Bạn cũng có thể sử dụng đường dẫn filesystem tuyệt đối, điều này hữu ích nếu script nằm bên ngoài thư mục project.

Dòng đầu tiên của ``sayhello.gd`` ở trên thường được gọi là *shebang*. Nếu tệp nhị phân Godot nằm trong ``PATH`` của bạn dưới dạng ``godot``, nó cho phép bạn chạy script như sau trên các bản phân phối Linux hiện đại cũng như macOS:

::

    # Mark script as executable.
    chmod +x sayhello.gd
    # Prints "Hello!" to standard output.
    ./sayhello.gd

Nếu cách trên không hoạt động với phiên bản Linux hoặc macOS hiện tại của bạn, bạn luôn có thể để shebang chạy Godot trực tiếp từ vị trí của nó như sau:

::

    #!/usr/bin/godot -s
